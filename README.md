# 커뮤니티 크롤러

여러 커뮤니티에서 **내가 정한 키워드**가 들어간 글을 모아 CSV/JSONL 로 떨어뜨린다.
키워드 판정은 전부 `config.json` 에 적힌 규칙을 코드가 집행한다 — 모델이 그때그때 고르지 않는다.
같은 설정이면 같은 결과가 나온다.

## 빠른 시작

```bash
node crawl.mjs --robots    # 어느 사이트를 긁어도 되는지 먼저 확인
node crawl.mjs --show      # 무엇을 몇 번 요청할지 미리보기 (요청 안 함)
node crawl.mjs             # 수집
```

결과는 `out/results.csv` (엑셀에서 바로 열림) 와 `out/results.jsonl` 에 쌓인다.

## 키워드 정하기

`config.json` 의 `keywords` 만 고치면 된다.

```json
"keywords": {
  "any":  ["이런 앱 없나", "일일이 입력"],   // 하나라도 있으면 통과 (OR)
  "all":  [],                                // 전부 있어야 통과 (AND)
  "none": ["공지", "쿠팡"],                  // 하나라도 있으면 탈락 (NOT, 최우선)
  "regex": ["없(나|을까)요?"],               // 정규식
  "searchQueries": { "use": [] }             // 사이트 검색창에 넣을 말. 비우면 any 를 그대로 씀
}
```

- 구절 안의 띄어쓰기는 AND 로 본다. `"일일이 입력"` 은 제목에 `일일이` 와 `입력` 이
  둘 다 있으면 맞는 것으로 친다 (커뮤니티 제목은 띄어쓰기가 제각각이라서).
- `searchQueries.use` 를 쓰면 **검색은 넓게, 저장은 좁게** 할 수 있다.
  예: 검색은 `"앱"` 으로 많이 긁어오고, `any` 로 원하는 것만 남긴다.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `node crawl.mjs` | config 대로 수집 |
| `node crawl.mjs --site ppomppu` | 한 사이트만 |
| `node crawl.mjs --pages 5` | 검색어당 페이지 수 |
| `node crawl.mjs --probe arca` | 한 번만 요청해서 연결·파서 진단 |
| `node crawl.mjs --robots` | 사이트별 robots.txt 판정 |
| `node crawl.mjs --show` | 요청 횟수·예상 소요 미리보기 |
| `node crawl.mjs --head` | 창을 띄워서 실행 (파서 깨졌을 때 눈으로 확인) |
| `node report.mjs --days 20` | 수집 결과를 날짜순으로 읽기 좋게 출력 |
| `node free.mjs --days 20` | 핫딜 중 '값이 0인 게임'만 골라 진행중/종료 판정 |
| `node test.mjs` | 4단계 자체검사 |
| `node tools/audit-claims.mjs` | 지어낸 값이 섞였는지 훑기 |
| `node server.mjs` | 웹 UI (http://127.0.0.1:8787) |

## 웹 UI

```bash
node server.mjs                                   # 내 PC 에서만
HOST=0.0.0.0 TOKEN=$(openssl rand -hex 24) node server.mjs   # 공개 (VPS)
```

화면에서 검색어·사이트를 고르고 누르면 진행 상황이 실시간으로 흐르고,
끝나면 결과가 한 번에 20개씩 쪽으로 나뉘어 나온다.

검색 하나는 세 단계다. *(2026-10-01 추가 — 아래 끝까지 찾기·주제 태그·그만도 같은 날)*

1. **비슷한 말 찾기** — 로그인된 Claude Code(`claude -p`)가 같은 뜻의 다른 표현을 뽑는다
2. **검수** — 새로 불린 Claude 가 후보를 하나씩 판정해 뜻이 같은 것만 남긴다 (연상어·너무 넓은 말은 뺀다)
3. **크롤링** — 원래 검색어 + 통과한 말로 `crawl.mjs` 를 돌린다

1·2단계는 화면에서 끌 수 있고, 실패하면 원래 검색어로만 3단계를 한다.
Claude 는 `--safe-mode` 로 불러서 훅(회의록 자동화 등)이 돌지 않는다.
모델은 `PAIN_MINER_MODEL` (기본 sonnet), 실행 파일은 `CLAUDE_PATH` 로 바꾼다.

- **끝까지 찾기** — 쪽 수 제한 없이 결과가 바닥날 때까지 넘긴다 (상한 300쪽).
  빈 쪽·같은 쪽 반복·연속 3번 실패에서 스스로 멈춘다. 기본은 꺼져 있다.
- **주제 태그** — 결과마다 게임·생활·쇼핑·IT … 태그가 붙는다 (`core/tags.mjs`, 규칙만 쓴다).
  누르면 그 주제만, ✕ 를 누르면 그 주제를 뺀다. 뺀 주제는 브라우저에 기억된다.
  근거는 게시판·갤러리 이름 → 아카 채널 주소 → 제목·본문 발췌 순이다.
- **그만** — 그때까지 모은 것을 저장하고 멈춘다.
- 사이트들은 동시에 돈다. 속도 제한은 호스트마다 따로 걸린다.

수집 로직을 웹용으로 새로 쓰지 않았다. `crawl.mjs` 를 그대로 실행한다 —
웹 결과와 터미널 결과가 다르면 둘 다 못 믿게 되기 때문이다.

`TOKEN` 없이 `HOST=0.0.0.0` 으로 시작하면 **서버가 거부한다.** 이 서버가 열리면
누구든 내 서버에서 남의 사이트로 요청을 날릴 수 있게 되기 때문이다.

배포는 `DEPLOY.md` 참고.

## 본문까지 받기

`engine.fetchBody: true` 면 걸러낸 글의 본문을 따로 받아온다.
마감일·쿠폰코드처럼 제목에 안 나오는 정보가 본문에 있다.

```json
"engine": { "fetchBody": true, "maxBodies": 60 }
```

목록을 다 훑은 **뒤에** 받는다. 목록 한 쪽에 글이 20개씩 나오므로 그때그때 받으면
요청이 20배로 튄다. `maxBodies` 상한은 사이트별로 번갈아 배분하므로, 먼저 수집된
사이트가 상한을 독식하지 않는다.

본문은 JSONL 에 전문이, CSV 에는 앞 500자가 들어간다.

Ctrl+C 로 끊어도 그때까지 받은 것은 저장된다.

## "창이 열려 있어야 들어가지는 사이트" — 어떻게 하나

`config.json` 의 `engine` 에서 정한다.

```json
"engine": {
  "mode": "auto",            // auto=HTTP 먼저, 막히면 브라우저 / http / browser
  "headless": true,          // true=창이 아예 안 뜸
  "offscreenWindow": false,  // headless:false 와 같이 쓰면 창을 화면 밖에 띄움
  "keepSession": true        // 쿠키를 실행 사이에 유지
}
```

- **평소**: `headless: true`. 진짜 Chrome 이 백그라운드에서 돌지만 화면에는 안 보인다.
- **헤드리스를 거부하는 사이트**: `headless: false` + `offscreenWindow: true`.
  진짜 창이 뜨되 `-3000,-3000` 위치라 눈에는 안 보인다.
- **파서가 깨졌을 때**: `--head` 로 창을 보면서 디버깅.

`keepSession: true` 면 쿠키·로컬스토리지가 `.session/` 에 남는다. 매번 새 손님처럼
들어가지 않으므로, 첫 방문자에게 검증 화면을 띄우는 사이트에서 매번 다시 걸리지 않는다.

## 403 / 405 / 404 가 뜰 때

원인이 셋인데 해법이 각각 다르다. `--probe` 가 어느 쪽인지 알려준다.

**1. 헤더가 브라우저 같지 않다 → 403**
User-Agent, Referer, `sec-fetch-*` 가 없으면 바로 거부된다. 한국 커뮤니티는 Referer
검사가 특히 심하다. `core/fetch.mjs` 가 실제 Chrome 과 같은 헤더를 갖춰 보내고,
어댑터마다 그 사이트가 기대하는 `referer` 를 지정해 둔다.

**2. TLS 지문이 브라우저가 아니다 → 403** ← 이게 진짜 함정이다
Cloudflare 류는 헤더가 아니라 **TLS 핸드셰이크 모양**을 본다.
2026-09-22 arca.live 실측:

| 방법 | 결과 |
|---|---|
| curl + 브라우저 UA | **200** |
| Node 내장 `fetch` + 똑같은 헤더 | 403 (헤더를 하나씩 빼봐도 전부 403) |
| 헤드리스 크롬 | 403 — "잠시만 기다리십시오…" 챌린지 |

그래서 전송은 **curl** 에 맡긴다. 헤더를 아무리 만져도 `fetch` 로는 못 푼다.
브라우저 폴백은 검증 화면이 스스로 풀릴 때까지 최대 20초 기다린다.

**3. 그 경로가 GET 을 안 받는다 → 405**
검색이 POST 폼인 경우다. 어댑터에 `method: 'POST'` 와 `body` 를 주면 된다.
**404** 는 대개 진짜로 주소가 틀린 것이다(게시판 id 변경 등) — 헤더로는 안 풀린다.

## 짧은 시간에 여러 글을 보면 막히는 것

막히지 않는 방법은 '안 들키는 것'이 아니라 **차단당할 짓을 안 하는 것**이다.
`core/limiter.mjs` 가 호스트마다:

- 요청 사이에 `minDelayMs + 무작위 지터` 를 강제한다 (고정 간격은 그 자체로 기계처럼 보인다)
- 429/403/503 을 받으면 그 호스트 대기시간을 **2배로 늘린다** (최대 5분)
- 연속 성공이 쌓이면 원래 속도로 천천히 되돌린다

즉 사이트가 "그만" 하면 더 세게 두드리지 않고 물러선다.
`rate.minDelayMs` 를 키우는 것이 차단을 피하는 가장 확실한 방법이다.

`output.resume: true` 면 이미 본 글은 `out/seen.json` 에 기록되어 다음 실행 때
건너뛴다. 매일 돌려서 새 글만 받을 수 있고, 같은 글을 다시 요청하지 않으니
상대 서버 부담도 준다.

## robots.txt 정책

사이트마다 `config.json` 에서 정한다. **판정은 언제나 하고, 집행 수위만 고른다.**

| 값 | 동작 |
|---|---|
| `enforce` | 거부면 요청하지 않는다 (기본값) |
| `warn` | 경고를 남기고 진행한다 |
| `off` | 확인조차 안 한다 |

### 누구에게 적용되는 규칙인가

robots.txt 는 각 클라이언트가 **자기 이름에 해당하는 그룹**을 따르는 규약이고,
이름이 없는 클라이언트는 `User-agent: *` 를 따른다. 이 도구는 ClaudeBot 이 아니라
사용자가 자기 PC 에서 돌리는 개인 수집기이므로 `*` 규칙이 우리 규칙이다.

예전 이 프로젝트는 'robots.txt 가 ClaudeBot 을 막으면 호스트 전체 거부' 로 짜여 있었다.
그건 틀렸고, 그 때문에 디시인사이드를 통째로 못 쓰는 곳으로 분류하고 있었다.

2026-09-23 실측:

| 사이트 | `User-agent: *` | 비고 |
|---|---|---|
| 아카라이브 · 개드립 · 뽐뿌 | 허용 | |
| 디시인사이드 | **허용** | AI 학습 크롤러(GPTBot·ClaudeBot·CCBot…)만 이름으로 차단.<br>갤러리 14곳은 `*` 에도 금지 (47, cat, dog, stock_new2 …) |
| 루리웹 | 검색 경로만 거부 | `Disallow: /*search_type=` — 목록 훑기(browse)는 허용 |

그래서 다섯 곳 모두 쓸 수 있다. 다만:

- 디시의 **금지 갤러리는 코드가 자동으로 막는다.** `config.json` 에 `stock_new2` 같은
  갤러리를 넣으면 `enforce` 정책이 요청 자체를 보내지 않는다.
- 루리웹은 `"listMode": "browse"` 로 검색 대신 목록을 훑는다.
- 디시가 AI 학습 크롤러를 막아뒀다는 사실은 `check()` 가 `aiBlocked` 로 알려준다.
  **모은 글을 모델 학습에 쓰는 것은 사이트가 명시적으로 거부한 용도다.**
  키워드 검색·읽기용으로 모으는 것과는 다른 이야기다.

### 마이너 갤러리

주제가 좁은 갤러리는 대부분 마이너 갤러리에 있다. 경로가 하나 더 붙는다.

```json
"boards": ["programming", "mgallery/game_dev", "mgallery/algo", "mgallery/godot"]
```

## 새 커뮤니티 붙이기

`adapters/index.mjs` 에 객체 하나만 추가하면 된다.

```js
const 새사이트 = {
  id: 'newsite',
  label: '새 사이트',
  referer: 'https://newsite.com/',     // 403 예방의 핵심
  charset: 'euc-kr',                   // EUC-KR 사이트만
  url: (board, kw, page) => `https://newsite.com/${board}?q=${encodeURIComponent(kw)}&p=${page}`,
  waitFor: 'td.subject',               // 브라우저 모드에서 기다릴 선택자
  parse(html, board) {
    return [{ board, title, url, date }];  // date 는 YYYY-MM-DD, 모르면 ''
  },
};
```

그 다음 `config.json` 의 `sites` 에 추가하고 `node crawl.mjs --probe newsite` 로 확인한다.

**검색이 진짜로 되는지 꼭 확인할 것.** 있을 수 없는 문자열로 검색해서 0건이
나와야 한다. 검색어를 무시하고 기본 목록을 돌려주는 사이트가 꽤 있다 —
개드립도 `index.php?mid=dogdrip&...` 형태가 그랬다(`/dogdrip?search_target=...`
형태라야 걸러진다).

날짜는 `readDate()` 를 쓰면 `2025.03.14` 와 `7 일 전` 을 둘 다 읽어준다.

## 구조

```
config.json          ← 보통 이 파일만 고치면 된다
crawl.mjs            진입점
core/
  fetch.mjs          curl 우선 → 막히면 브라우저. 헤더·쿠키·인코딩
  browser.mjs        헤드리스 Chrome, 세션 유지, 검증 화면 대기
  limiter.mjs        호스트별 속도 제어 + 적응형 백오프
  robots.mjs         robots.txt 판정 (집행 수위는 config 가 정함)
  keywords.mjs       AND/OR/NOT/정규식 판정 엔진
  store.mjs          CSV·JSONL 출력, 중복 제거, 이어받기
adapters/index.mjs   사이트별 URL 생성 + 목록 파싱
test.mjs             4단계 자체검사
tests/fixtures/      파서 검증용으로 저장해둔 실제 HTML
```

`.session/` 에는 쿠키가 들어간다. 이상해지면 지우고 다시 돌리면 된다.

### 4단계가 하는 일

'돌았다'와 '맞는 걸 가져왔다'는 다른 문제다. 제목을 엉뚱한 URL 에 붙이거나,
없는 날짜를 채워 넣거나, 목록에 없던 글이 섞여도 통계는 멀쩡해 보인다.
그래서 4단계는 저장된 행을 들고 **원본으로 되돌아가 대조한다**:

- 저장된 제목을 목록 HTML 에서 다시 찾는다 → 없으면 지어낸 것
- 저장된 URL 로 직접 가서 그 페이지에 그 제목이 있는지 본다 → 없으면 제목·링크가 엇갈린 것
- 목록을 다시 받아 다시 파싱해 날짜가 그대로 재현되는지 본다 → 어긋나면 저장 단계에서 채워 넣은 것
- 본문을 다시 받아 저장된 본문과 대조한다
- `matched` 에 적힌 키워드가 제목에 실제로 있는지 본다

'모든 날짜가 같다'는 것만으로는 실패시키지 않는다 — 핫딜 게시판 1쪽은
원래 전부 오늘 글이다 (실측 23건 전부 같은 날). 대신 재현성으로 판정한다.

## 알아둘 것

- **아카라이브는 제목+본문을 검색**한다. 반면 키워드 판정은 제목만 본다.
  그래서 아카라이브는 긁어온 것에 비해 남는 게 적다. 본문까지 보고 싶으면
  글 본문을 따로 받아오는 단계가 필요하다.
- `filters.sinceDate` 가 오래된 글을 대량으로 걸러낸다. 처음 돌릴 때 결과가
  적으면 이 값부터 확인할 것.
- 이전 버전 파일(`mine.mjs`, `sources.mjs`, `analyze.mjs` 등)은 그대로 두었다.
  새 파이프라인은 `crawl.mjs` 쪽이다.
